# i18n Integration Design

**Date:** 2026-03-29
**Status:** Approved

## Overview

Integrate internationalization into the Next.js 15 App Router template using `next-intl`. Supports Czech (`cs`, default, no URL prefix) and English (`en`, `/en/` prefix). All pages remain statically generated (SSG).

## Locales & URL Strategy

- `cs` — default locale, no URL prefix (`example.com/`, `example.com/about`)
- `en` — secondary locale, prefixed (`example.com/en/`, `example.com/en/about`)
- Middleware detects locale from `Accept-Language` header and redirects `/` accordingly

## File Structure

```
src/
├── app/
│   └── [locale]/
│       ├── layout.tsx        # locale-aware root layout
│       └── page.tsx          # home page
├── i18n/
│   ├── routing.ts            # locales array + defaultLocale
│   ├── request.ts            # getRequestConfig — loads message file per locale
│   └── navigation.ts         # typed Link, redirect, useRouter, usePathname
└── messages/
    ├── cs.json               # Czech strings (default)
    └── en.json               # English strings
middleware.ts                 # project root — locale detection + redirect
```

The existing `src/app/layout.tsx` is replaced by `src/app/[locale]/layout.tsx`. All other app structure (Lenis provider, font, globals.css) stays intact.

## SSG

Every page under `[locale]/` exports `generateStaticParams`:

```ts
export async function generateStaticParams() {
  return [{ locale: "cs" }, { locale: "en" }];
}
```

`setRequestLocale(locale)` is called at the top of every Server Component layout and page to opt out of dynamic rendering. Without this, `next-intl`'s internal `headers()` read forces dynamic mode.

## Translations

- JSON files: `messages/cs.json` and `messages/en.json`
- Nested structure, e.g. `{ "home": { "title": "STARTER" } }`
- Server Components use `getTranslations("namespace")`
- Client Components use `useTranslations("namespace")`
- TypeScript global type declaration (`next-intl.d.ts`) points at `messages/cs.json` for autocomplete and compile-time key safety

## Navigation Utilities

`src/i18n/navigation.ts` re-exports locale-typed navigation helpers from `next-intl`:

```ts
export const { Link, redirect, usePathname, useRouter } = createNavigation(routing);
```

All internal links use this `Link` instead of `next/link` — locale prefix is injected automatically.

## Middleware

`middleware.ts` at project root uses `createNavigation(routing).middleware`:

- Runs on all non-static, non-api routes
- Detects locale, sets cookie, redirects if needed
- Does not affect static page generation

## Dependencies

- `next-intl` (latest stable) — added to `dependencies`
